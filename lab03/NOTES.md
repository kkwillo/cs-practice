git diff — для сравнения состояний и просмотра изменений.
git show — для детального просмотра одного коммита.
git log — для анализа истории коммитов с фильтрацией.
git log -S — для поиска коммитов по строке, которая была добавлена или удалена.
git blame — для отслеживания истории строк в файле.

git restore файл` восстанавливает файл из последнего коммита (HEAD)
  и уничтожает все некоммиченные правки в нём.
git restore --source=<commit файл берёт файл из указанного коммита,
  т.е. позволяет достать любую старую версию в рабочую папку,
  не меняя историю.
Опасность: обе команды перезаписывают рабочую копию. Если правки не
  закоммичены, они теряются безвозвратно — Git не хранит их нигде.

git revert HEAD создал новый коммит, который делает изменения
  ошибочного коммита в обратную сторону. История не переписывается:
  плохой коммит остаётся виден, но нейтрализован.
git reset --hard commit же УДАЛЯЕТ коммиты из истории —
  ветка будто бы их никогда не содержала.
В опубликованной истории (которую уже скачали другие / сервис проверки)
  reset --hard опасен: чужие копии расходятся с вашей, история
  переписывается, конфликты неизбежны. revert безопасен: он просто
  добавляет коммит и раскатывается через обычный push.


Тег — это постоянное имя (ссылка) для одного конкретного коммита.
  Он не двигается: v1.0 навсегда привязан к этому коммиту.
Ветка — тоже ссылка на коммит, но подвижная: она автоматически
  сдвигается на каждый новый коммит. Поэтому теги используют для релизов
  (v1.0 легко найти через полгода), а ветки — для разработки.
